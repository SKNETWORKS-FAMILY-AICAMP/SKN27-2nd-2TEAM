# 🤖 머신러닝 핵심 작업 가이드

## 1. 개요
본 가이드는 머신러닝 모델 구축 시 실무자가 즉시 참고할 수 있도록 전체 과정을 핵심 위주로 압축한 문서입니다. 작업의 특성에 따라 **1) 데이터에 따라 달라지는 부분**, **2) 공통 처리 부분**, **3) 자동화 가능 부분** 세 가지로 나누어 가이드합니다.

### 🔄 전체 작업 흐름 요약

**[1. 데이터 의존 영역]** `데이터 이해 (분포 파악, 결측/이상치 확인)` ➔ `Feature 설계 (변수 선정, 파생 변수 생성)` ➔ `전처리 정책 결정 (결측치 대치, 스케일링, 인코딩)`
⬇
**[2. 공통 처리 영역]** `파이프라인 구축 (전처리 로직 함수화, 학습/추론 일치)` ➔ `Baseline 학습 (기본 모델 성능 측정)` ➔ `모델 세트 저장 (전처리 객체와 묶어서 저장)`
⬇
**[3. 자동화 가능 영역]** `파라미터 튜닝 (GridSearch/Optuna 최적화)` ➔ `실험 로깅 (모델, 파라미터, 성능 자동 기록)` ➔ `검증 및 리포팅 (극단값 예외 테스트, 성능 시각화)`

---

## 2. 데이터에 따라 달라질 수 있는 부분 (분석 및 기획 단계)
데이터셋의 고유한 특성(도메인, 분포 등)에 따라 작업자의 판단과 기획이 필수적으로 개입되어야 하는 단계입니다.

* **데이터 이해 (EDA) 및 기준 수립**
  * 데이터 타입, 분포, 결측값 및 이상치 파악
  * 도메인 지식을 활용한 불필요/중복 데이터 제거 기준 수립
* **Feature(변수) 설계**
  * 모델에 실제로 사용할 핵심 변수 선정 및 파생 변수 기획
  * 종속 변수(Target)와 독립 변수 간의 관계 분석
* **전처리 정책 결정**
  * 결측값 대치 방법(평균, 중앙값, 최빈값 등), 스케일링 여부, 범주형 데이터 인코딩 방식 등 데이터 특성에 맞는 변환 방식 결정

---

## 3. 데이터와 관계없이 공통으로 처리되는 부분 (표준화 영역)
어떤 데이터를 다루더라도 동일한 구조와 원칙 하에 필수적으로 진행되어야 하는 과정입니다.

* **재사용 가능한 전처리 파이프라인 구축**
  * 설계된 전처리 정책을 함수/클래스 형태로 구현
  * **[중요]** 학습(Train) 단계와 실제 서비스 추론(Inference) 단계에서 완전히 동일한 전처리가 적용되도록 구조화
* **Baseline 모델 학습 및 평가**
  * 복잡한 모델 이전에 가장 단순한 형태의 모델(Baseline)을 학습하여 성능의 기준점 확보
  * 데이터 타입(분류, 회귀 등)에 맞는 공통 평가 지표(Accuracy, F1-Score, RMSE 등)로 성능 측정
* **모델 세트 저장 및 버전 관리**
  * 학습 완료된 모델뿐만 아니라 **전처리 객체(Scaler, Encoder 등)**를 반드시 한 세트로 묶어서 저장

---

## 4. 프로그래밍으로 자동화할 수 있는 학습/평가 이후 과정
파이썬 스크립트나 파이프라인 도구로 한 번 구축해두면, 이후 사람의 개입 없이 반복 수행할 수 있는 시스템 영역입니다.

* **하이퍼파라미터 튜닝 자동화**
  * GridSearchCV, Optuna 등을 활용하여 모델 성능을 극대화하는 최적의 파라미터 조합 탐색을 자동 수행
* **실험 결과 로깅 (로깅 자동화)**
  * 모델이 학습될 때마다 사용된 Feature, 하이퍼파라미터, 성능 지표 등을 파일이나 DB(예: MLflow, WandB 등)에 자동 기록
* **시뮬레이션 및 극단값 검증 (테스트 자동화)**
  * 비정상 값, 결측치, 극단값 등을 고의로 입력해보고 모델 파이프라인이 에러 없이 예외 처리를 수행하는지 검증하는 테스트 코드 구축
* **설명 자료 및 리포팅 생성 자동화**
  * 평가 지표 그래프(ROC Curve 등), Feature Importance(변수 중요도) 차트 등을 코드로 자동 시각화하여 결과 보고서 생성

---

## 5. 핵심 원칙 3가지
1. **분석은 유연하게, 처리는 표준화되게, 평가는 자동화되게 한다.**
2. **학습에 사용된 전처리 로직은 실 서비스 추론 환경에서도 100% 동일하게 동작해야 한다.**
3. **모든 모델 변경점과 평가 결과는 반드시 기록으로 남긴다.**
